# motion-library（动作库）第一期报告

日期：2026-08-13
仓库：https://github.com/Gousting/motion-library（私有，Gousting/motion-library）

## 一、项目定位（已落地）

动作库 = R2V 参考生视频的「动作模板」资产管理，与 image-gen 的风格 registry 对称：
- 风格锁画面质感（image-gen 的 style registry）
- 动作锁运动形态（本项目的 motion library）

R2V 验证硬结论（2026-08-13）：动作迁移质量取决于参考视频的动作清晰度——
全景背影走路 62 分（动作丢失），腿部步态特写（黑底）88 分（动作自然复刻）。
故动作模板沉淀成资产，入库前必跑 R2V 验证实测迁移质量，不凭肉眼感觉定级。

## 三、元数据规范（meta.yaml）

每条动作 16 个顶层字段（15 标量 + r2v_checks 字典），字段表见 README「元数据规范」：
id / action_type / sub_action / camera / body_part / clarity_grade / duration_sec /
resolution / fps / source_type / source_url / license / style_pollution / r2v_verified /
r2v_score / r2v_checks{char_locked, motion_natural, spatial_stable}

- 枚举：camera=full/medium/closeup；body_part=full_body/half_body/legs/hands/face；
  clarity_grade=A/B/C；source_type=stock/selfshot/reuse；license=pexels-free/self-shot/derived
- 校验：scripts/schemas.py 的 validate_meta() 检查必填缺失、类型错误、枚举越界、
  r2v_score 0-100、r2v_checks 三项完整性、id 无空白。

index.yaml：按 action_type 分组，条目摘要 = id + sub_action + camera + body_part +
clarity_grade + r2v_score + path，分组内按 grade(A/B/C) 再按 r2v_score 降序。

## 四、ingest 流程（已实现并跑通）

```
python scripts/ingest.py --video <候选视频> --action-type walk --camera closeup \
    --body-part legs --source-type stock --source-url <url> --license pexels-free \
    [--sub-action slow_walk] [--style-pollution] [--seed N]
```

流程：
1. 调 preprocess：ffmpeg 裁 3-5s / 24fps / 1344x768（保持比例 pad 黑边）/ 可选 crop 去遮挡
2. 调 ComfyUI R2V：ref_images=[assets/test_character.png]，ref_videos=[模板转帧]，中性场景 prompt
3. 调 VLM 三项审查（char_locked/motion_natural/spatial_stable）+ 总分
4. 自动评级：score>=80 A；70-79 B；<70 C（打印「弃用」退出，不入库不写 meta）
5. 写 meta.yaml + 登记 index.yaml + 落盘 template.mp4/source.mp4
6. 打印入库结果（id + grade + score + 三项判断）

- 复用已验证动作：`--verified-score N --verified-checks "char_locked=true,..."`（reuse 模式，跳过 R2V+VLM）
- 评级脚本只调 ComfyUI HTTP API（MiniMaxH3ReferenceToVideo + ref2va 权重），不直接读写权重文件。
- 已踩坑沉淀：LoadImagesFromFolderKJ 标 optional 实为必填（image_load_cap=0/start_index=0）；
  autogrow 输入用扁平点号键 ref_images.ref_image_0 / ref_videos.ref_video_0。

## 六、评级映射规则（纯函数，已单测）

score_to_grade(score)：>=80 → A；70-79 → B；<70 → C（单测覆盖边界 79/80、69/70）。
auto_grade(score, checks)：
- score < 70 → C，弃用（不入库）
- 70-79 → B（标注风险）
- >=80 且三项全 true → A；任一 false → 降级 B（动作迁移不干净，标注风险）

## 七、与 ai-video-pipeline 的关系（已落地）

（锁画面质感），动作 ID→本项目的 index.yaml 索引（锁运动形态）。

## 八、验证结果（已实现项）

1. pytest 全绿：38 passed（评级边界、meta 校验、index 登记、R2V 工作流/中性 prompt/预处理命令纯函数）。
2. 种子入库真实跑通：reuse 模式产出 meta.yaml + template.mp4 + index 登记，全字段校验通过。
3. 全链路 smoke 测试（preprocess→R2V→VLM→评级→弃用判断）真实跑通 5 次，均正确产出：
   - preprocess 从 raw 源（1920x1080@30fps 10.27s）复现的 template.mp4 与原验证产物字节一致（732955B）；
   - R2V 经 ComfyUI HTTP API 生成结果（~800KB mp4，96 帧），角色锁定、空间稳定均 true；
   - VLM 三项审查正常，score<70 正确走「弃用」路径（不入库不写 meta）。

4. 【关键发现】中性场景动作迁移偏弱：
   用同一动作模板、同一测试角色图、同一种子 20260814（原 88 分那次所用种子），
   仅把 prompt 场景从「雨夜便利店（原 88 分验证）」换成「简洁室内中性灰背景」，
   动作迁移质量显著下降（5 次 smoke 得分 45/55/55/55/48，motion_natural 均 false，
   角色僵立只推镜），而角色锁定、空间稳定仍 true。
   说明：R2V 动作迁移对 prompt 场景/运镜描述高度敏感，「中性灰室内 + 静态构图」易触发
   模型进入「静态肖像」模式，忽略参考视频的动作信号。
   已据实迭代中性场景 prompt（移除「stands centered/centered in frame」、显式写
   「must NOT stand still」、加「walks toward and past the camera + camera tracking backward」、
   把动作描述写进 <Video 1> 段），但仍未复现 88 分。

   结论：种子 walk_slow_legs_001 的 r2v_score=88 来自之前「雨夜便利店」场景的验证（按任务书
   「meta 写 r2v_score=88」指示），与中性场景评级标准并存。中性场景评级标准（任务书硬性设计，
   为避免复杂场景干扰动作评分）在当前 R2V 模型下对动作迁移偏保守，后续动作入库时
   中性场景评分可能系统性偏低——这是需要在下一期继续调优（场景措辞 / 多 seed 平均 / 阈值标定）
   的已知点，不在本期改动范围。

- 根因定位：不是场景不够丰富，是机位措辞诱导推镜——「one-point perspective / sidewalk receding
